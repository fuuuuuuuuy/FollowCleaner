## 这是什么

FollowCleaner 是一个桌面端工具，帮助你把**微信（公众号 / 视频号）、哔哩哔哩、小红书**等平台的关注列表集中到一处，进行：

- **分类归档**：多级分类树 + 标签，给每一个关注对象安个"家"
- **多维筛选**：按平台、关注时间、互动频率、账号类型快速定位
- **批量操作**：批量选择、批量归类、批量导出
- **一键清理**：在分类视图中直接取消关注，支持批量取关 + 确认机制 + 回收站兜底
- **数据安全**：所有数据仅存储在本机，不上传任何服务器；开源可审计

## 为什么做它

各平台关注列表只增不减：几百上千个关注里，大量是"关注后再也没看过"的账号。但平台官方：

- 不提供跨平台的统一管理视图
- 不提供多级分类能力（B站/小红书仅有简单分组）
- 微信甚至没有关注列表导出入口，取关只能逐个手动操作

FollowCleaner 用"平台适配器（Platform Adapter）"架构把各平台差异收敛到统一数据模型，未来新增平台只需实现一个适配器接口。

## 架构概览

```
┌──────────────────────────────────────────────┐
│                前端（React + TS）              │
│  分类树 │ 账号列表 │ 详情面板 │ 批量工具栏     │
├──────────────────────────────────────────────┤
│              Tauri 壳（IPC / 自动更新）         │
├──────────────────────────────────────────────┤
│            Rust 核心（本地 SQLite）            │
│  ┌─────────────┬─────────────┬─────────────┐ │
│  │ WeChat      │ Bilibili    │ Xiaohongshu │ │  ← Platform Adapter 插件化
│  │ Adapter     │ Adapter     │ Adapter     │ │
│  └─────────────┴─────────────┴─────────────┘ │
│  数据获取分级：手动导入 ＞ 本地只读 ＞ 自动化    │
└──────────────────────────────────────────────┘
```

## 快速开始（V0.1 开发版）

环境要求：Node.js ≥ 18、pnpm、[Rust](https://rustup.rs)（stable）、Windows 需 WebView2（Win11 自带）。

```bash
pnpm install        # 安装前端依赖
pnpm tauri dev      # 启动桌面应用（首次会编译 Rust，需数分钟）
```

快速体验：应用内点击「导入关注列表」→ 下载模板，或直接导入仓库自带的
[examples/sample-follows.csv](./examples/sample-follows.csv) 示例数据，
即可体验分类树、多维筛选、批量分配、导出等全部 V0.1 功能。

> 数据全部保存在本机应用数据目录（`followcleaner.db`），不上传任何服务器。

## 当前状态与贡献

**V0.1 MVP「整理盒」已完成**：手动导入（CSV/JSON 模板 + 校验 + 去重）、多级分类树（拖拽排序/5 级上限）、多维筛选与搜索、批量分配分类、数据导出、本地 SQLite 加密存储。

**V0.5「B站自动接入」已完成**：哔哩哔哩扫码登录（SESSDATA 会话仅存本机）→ 自动拉取全部关注列表入库 → 应用内直接批量取关（二次确认、3~8 秒随机限速、平台风控自动熔断、实时进度）。

后续路线：V1.0 小红书适配器 + 仪表盘 → V1.1 微信高级模式。微信因无网页接口，只能通过本机数据库只读方式接入（L3 高级模式），与B站的网页登录（L2）路径不同，详见 [合规文档](./docs/compliance-privacy.md)。

开发路线图见 [docs/backlog-roadmap.md](./docs/backlog-roadmap.md)。
