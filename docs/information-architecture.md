# FollowCleaner 信息架构与核心流程

## 1. 信息架构（IA）

组织方式：以**层级式**为主（工具型产品，功能边界明确），列表浏览辅以**面式筛选**（多维 facet）。

### 1.1 一级导航（侧边/标签页）

1. **概览**（Dashboard）——关注体检首页
2. **工作台**（核心）——分类树 + 账号列表 + 详情
3. **回收站**——取关快照与恢复
4. **数据源**——适配器管理与导入入口
5. **设置**——安全、备份、关于

### 1.2 页面清单

#### P1 概览页（Dashboard）
- 页面用途：关注健康度总览、清理入口
- 入口：应用启动默认页 / 侧边导航
- 出口：点击图表 → 工作台（带筛选）；点击"开始清理" → 工作台
- 核心元素：关注总数卡、平台分布饼图、互动频率分布柱图、关注时间分布、累计清理成果、快捷操作（导入数据/开始清理）

#### P2 工作台（三栏）
- 页面用途：浏览、筛选、分类、批量操作、取关的主场景
- 入口：概览页 / 侧边导航 / 导入完成跳转
- 出口：详情面板跳平台主页；取关确认弹窗；批量工具栏
- 核心元素：
  - 左栏：分类树（含"未分类"、平台默认分类、递归显示开关）、标签列表
  - 中栏：筛选器条（平台/类型/时间/互动/状态 chips）、搜索框、排序、视图切换、账号列表（虚拟滚动、首列勾选、表头全选）
  - 右栏：账号详情（头像/昵称/平台/类型/关注时间/互动数据/所属分类标签/备注/操作：打开主页·取关）
  - 底部：批量操作浮动工具栏

#### P3 导入向导（Modal/独立页）
- 步骤：① 选择平台 → ② 选择获取方式（手动/适配器）与风险说明 → ③ 数据处理告知确认 → ④ 执行（进度）→ ⑤ 结果预览与确认 → ⑥ 完成报告
- 特殊：微信高级模式在②③之间插入"高级功能授权与免责声明"页

#### P4 分类管理（内嵌左栏 + 弹窗）
- 新建/重命名/删除分类弹窗；拖拽排序在左栏直接完成

#### P5 取关确认弹窗
- 待取关清单、风险提示、倒计时确认按钮、"移入回收站"说明

#### P6 取关执行页/抽屉
- 队列进度（成功/失败/跳过）、暂停/终止按钮、风控熔断提示、失败项重试

#### P7 回收站
- 快照列表（昵称/平台/取关时间/主页链接）、重新关注（跳平台）、彻底移除、30 天过期提示

#### P8 操作日志
- 时间线：时间/动作/对象/平台/结果，支持按动作类型过滤

#### P9 数据源管理
- 适配器卡片（名称/版本/能力矩阵/风险等级/启用开关/支持版本说明）、导入历史记录

#### P10 设置
- 安全（二次确认、限速档位、数据库密码）、备份与恢复、匿名统计开关（默认关）、关于/免责声明

### 1.3 页面流转图

```
[P1 概览]
   ├── 开始清理 ───────────────→ [P2 工作台]
   │     ├── 点击账号 ─────────→ 右栏详情 ──打开主页──→ 外部平台
   │     ├── 勾选+批量工具栏 ──→ [P4 分类弹窗] / 导出
   │     │                     └→ [P5 取关确认] ──→ [P6 执行队列]
   │     │                                              └→ 成功账号写入[P7 回收站]
   │     └── 左栏分类树管理 ──→ [P4]
   ├── 导入数据 ───────────────→ [P3 导入向导] ──完成──→ [P2 工作台]
   ├── 回收站 ─────────────────→ [P7] ──重新关注──→ 外部平台主页
   ├── 数据源 ─────────────────→ [P9] ──导入──→ [P3]
   └── 设置 ───────────────────→ [P10]（含[P8 操作日志]入口）
```

## 2. 核心流程

### 2.1 首次导入流程

**目标**：用户完成首个平台关注数据导入
**起点**：首次启动（空库）
**终点**：工作台展示已导入账号
**预期步数**：3~6 步（取决于获取方式）

```
启动 → 空状态引导 → [导入向导]
  ① 选择平台（微信/B站/小红书/手动）
  ② 选择方式
       ├── 手动：下载模板 →（用户平台侧整理）→ 上传文件 → 校验
       ├── B站/小红书：环境自检 → 安全授权（会话/Cookie 本机保存）→ 拉取
       └── 微信：高级模式未开启？→ 展示授权+免责 → 确认 → 检测客户端/DB
              → 解密读取（失败→降级手动导入）
  ③ 数据处理告知（仅本机、不上传）→ 勾选确认
  ④ 执行解析（进度条）
  ⑤ 预览（账号数/字段完整度/重复项）→ 确认写入
  ⑥ 完成报告（成功/失败/跳过，失败可下载报告）
```

**异常分支**：
- 环境自检失败（客户端未运行/版本不支持）→ 原因说明 + 手动导入降级
- 文件错误 → 逐行报告，0 写入
- 网络中断 → 断点续传/重试

### 2.2 批量清理流程（主价值路径）

**目标**：筛选沉睡账号并安全批量取关
**起点**：工作台
**终点**：结果报告 + 回收站可查

1. 工作台：选择"零互动"互动频率 + "关注超 1 年"时间筛选
2. 系统实时展示结果数（如 320）
3. 用户点击表头复选框 → "全选筛选结果 320 个"
4. 底部工具栏 → 取消关注
5. 确认弹窗：浏览清单 → 阅读风险提示 → 倒计时结束 → 点击"确认取关"
6. 执行队列：限速执行，进度实时更新
7a. 正常完成 → 结果报告（成功 305/失败 15）→ 失败项可重试
7b. 风控信号 → 自动暂停 → 用户去平台完成验证 → 回来继续
8. 成功账号进入回收站（30 天可跳回重新关注）

**关键决策点**：
| 决策点 | 选项A | 选项B | 推荐 | 理由 |
|--------|-------|-------|------|------|
| 批量取关前是否强确认 | 直接执行 | 弹窗+倒计时 | B | 高危不可逆操作，防误触 |
| 风控信号处理 | 自动重试 | 熔断暂停 | B | 重试加剧风控，可能封号 |
| 取关后数据 | 直接删除 | 回收站保留30天 | B | 提供反悔路径 |
| 手动导入数据源取关 | 允许（提示手动） | 置灰+引导 | B | 工具无执行通道，置灰避免误解 |

### 2.3 分类整理流程

1. 左栏新建分类体系（如 素材源/常看/朋友/待清理）
2. 中栏筛选/搜索目标账号
3. 多选 → 拖到左栏节点 或 工具栏"分配分类"
4. 需要跨维度组织时打标签
5. 删除分类 → 确认 → 账号归入"未分类"（可在回收站撤销分类删除，V1.1）

## 3. 状态机

### 3.1 账号（FollowAccount）状态

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| following（关注中） | 已导入且未取关 | 分配分类/标签、取关、导出 |
| unfollow-pending（取关队列中） | 在取关队列等待/执行 | 暂停队列、移出队列 |
| unfollowed（已取关） | 取关成功 | 查看（回收站）、跳回平台重新关注 |
| unfollow-failed（取关失败） | 平台返回失败 | 重试、跳过 |

```
following ──提交取关──→ unfollow-pending ──成功──→ unfollowed
    ↑                        │                        │
    │                        ├──失败──→ unfollow-failed ──重试成功──→ unfollowed
    │                        │              │
    └── 队列中移除/终止 ──────┘              └──跳过──→ following（标记本次未处理）
unfollowed ──平台侧重新关注+重新导入──→ following
```

### 3.2 导入任务状态

`idle → self-check（环境自检）→ authorized（授权/文件就绪）→ parsing（解析中）→ preview（预览）→ writing（写入中）→ done`
异常分支：`self-check → failed-blocked（降级手动）`；`parsing → failed-report（错误报告）`

### 3.3 取关队列状态

`queued → running →（paused ↔ running）→ completed`
异常：`running → risk-paused（风控熔断，等待用户处理后回 running）`；`running/paused → terminated（用户终止，断点持久化）`

## 4. 交互设计原则

1. **危险操作三级防护**：清晰清单预览 → 强确认（批量倒计时）→ 可恢复（回收站）
2. **永远有降级路径**：任何适配器失败都能回到"手动导入"，不卡死用户
3. **本地优先反馈**：所有操作即时本地响应，平台侧动作异步队列化，不阻塞界面
4. **空状态即引导**：无数据时引导导入；无筛选结果时建议放宽条件
5. **能力矩阵驱动 UI**：适配器不支持的能力直接置灰并说明，不暴露会失败的操作
6. **层级克制**：分类最多 5 级；导航不超过 2 级到达任何核心功能
7. **反模式规避**：无不可逆裸操作、无"死胡同"错误页、跨页选择状态保留
