# FollowCleaner 竞品分析报告

## 1. 分析目标

1. 明确"多平台关注列表管理"这一细分需求的市场空白与差异化切入点
2. 验证核心功能（跨平台聚合、多级分类、批量取关）的必要性与用户价值
3. 确定合规、可持续的产品形态，规避法律与平台风控风险
4. 为产品定位与 MVP 范围取舍提供依据

## 2. 竞品选择

| 竞品 | 类型 | 定位 | 目标用户 | 选择理由 |
|------|------|------|----------|----------|
| B站「关注分组」 | 平台官方功能 | 单平台关注分组管理 | B站重度用户 | 官方能力天花板基准 |
| 小红书「收藏/关注分组」 | 平台官方功能 | 单平台内容收藏管理 | 小红书用户 | 官方分类能力基准 |
| 微信「公众号」列表 | 平台官方功能 | 公众号订阅浏览 | 微信用户 | 核心痛点来源（无导出/无分类） |
| 微信聊天记录导出工具（如留痕/WeChatMsg 类开源项目） | 桌面开源工具 | 微信本地数据解密导出 | 数据备份需求用户 | 微信数据获取技术路径参考 |
| 批量取关/粉丝管理脚本（油猴脚本、淘宝售卖脚本） | 脚本工具 | 单平台批量取关 | 运营人员 | 批量操作需求真实性验证 |
| RSS/订阅管理工具（如 RSSHub + 阅读器） | 间接竞品 | 信息源聚合订阅 | 信息效率控 | "统一管理信息源"心智参考 |

## 3. 市场格局

**3.1 需求侧：关注列表"只进不出"是普遍痛点**

- 用户关注行为高频、取关行为低频，关注列表随使用年限线性膨胀（数百到数千）。
- 平台算法以"关注"为正向信号，产品设计上系统性地**弱化取关入口**（入口深、无批量、无管理视图）。
- 跨平台时代，用户的关注关系分散在 5-10 个 App 中，没有任何一个官方产品提供跨平台视图。

**3.2 供给侧：官方无意做，灰色工具不敢做**

- **官方平台**：关注数是平台留存与内容消费的基础指标，没有动力提供"高效取关"工具。
- **灰色脚本**：油猴脚本/售卖外挂普遍存在，但单点功能、无分类管理、安全无保障、易随平台改版失效，且有封号风险。
- **开源工具**：微信数据导出类开源项目（读取本地数据库）已验证"用户读取自己设备数据"的技术路径与社区接受度，但此类工具聚焦聊天记录备份，**无人做"关注关系管理"这一垂直场景**。

**3.3 行业阶段**：细分赛道处于空白期（无直接竞品），需求真实但分散，适合开源工具切入、靠口碑传播。

### 4.3 结构层（信息架构）

- **官方功能**：关注入口埋在"我的"页面二级，列表即全部，无独立管理工作台。
- **导出工具**：技术导向界面，数据库表/字段思维，普通用户难以上手。
- **FollowCleaner**：以"管理工作台"为核心——左侧分类树、中间账号列表、右侧详情，符合文件管理器/邮件客户端的成熟心智模型，学习成本低。

### 4.4 框架层（交互体验）

| 关键任务 | 官方功能步数 | 取关脚本 | FollowCleaner 目标 |
|----------|-------------|---------|-------------------|
| 找出"半年没互动的关注" | 无法完成 | 无法完成 | 筛选器 2 次点击 |
| 给 50 个账号归类 | 无此能力 | 无此能力 | 多选 + 拖拽/批量分配 ≤ 4 步 |
| 批量取关 30 个账号 | 30 次重复操作（B站/小红书）；微信无法批量 | 一键但无确认 | 筛选→多选→确认弹窗→执行，全程可中断 |
| 误取关后恢复 | 不可恢复（需重新搜索关注） | 不可恢复 | 回收站保留快照，可跳回平台重新关注 |

### 4.5 表现层（视觉与品牌）

- 官方：平台品牌风格，内容消费导向。
- 脚本：无设计可言。
- FollowCleaner：工具型产品的克制设计——高密度信息、清晰分区、危险操作强警示；中性品牌，不使用任何平台商标元素。

## 5. SWOT 分析

| | 有利因素 | 不利因素 |
|--|---------|---------|
| **内部** | **S 优势**：① 无直接竞品，抢占"跨平台关注管理"心智；② 适配器架构可快速扩展平台；③ 开源+全本地，隐私信任度高；④ 回收站/限速/确认机制形成体验差异 | **W 劣势**：① 微信数据获取依赖逆向，版本升级需持续维护；② 自动化取关有风控边界，不能承诺 100% 成功；③ 个人开源项目，维护资源有限 |
| **外部** | **O 机会**：① 用户"数字断舍离"意识上升；② 微信导出类开源项目已教育市场、验证路径；③ 平台官方永远不会做此功能，无被官方吞并风险；④ 内容平台（B站/小红书社区）适合口碑传播 | **T 威胁**：① 平台改版导致适配器失效；② 自动化操作触发账号风控的用户投诉；③ 平台方法律投诉（DMCA/举报下架）；④ 黑灰产脚本以同名混淆视听 |

## 6. 差异化策略

### 6.1 核心机会点

1. **跨平台聚合**是所有官方与灰色工具都没做的空白——用户关注关系天然分散。
2. **"互动频率"维度**是取关决策的关键依据（"我还看TA吗？"），官方不提供，却是清理动作的核心抓手。
3. **安全兜底**（确认、限速、回收站）是灰色脚本与官方功能都没有的，直接消除用户"不敢批量操作"的心理门槛。
4. **合规分级**让产品能公开传播：默认手动导入完全合规，高风险能力显式启用、风险自担。

### 6.2 产品定位

> **FollowCleaner = 关注关系的"文件管理器 + 断舍离助手"**
> 一句话：把分散在各平台的关注列表汇总到本地，像整理文件一样分类，像清理衣柜一样安全地取关。

### 6.3 功能差异化矩阵

| 功能维度 | 竞品做法 | FollowCleaner 差异点 | 用户价值 |
|----------|----------|---------------------|----------|
| 跨平台 | 全部单平台 | 统一数据模型 + 适配器插件 | 一处管理所有关注 |
| 数据获取 | 要么不能导，要么纯逆向 | 三级降级：手动导入 → 本地只读 → 自动化 | 合规优先，永远有可用路径 |
| 分类 | 单级分组/无 | 多级树 + 拖拽排序 + 标签 | 管理上千账号不乱 |
| 批量取关 | 官方无；脚本裸奔 | 筛选→预览→确认→限速执行→回收站 | 敢用、不误伤 |
| 隐私 | 脚本不透明 | 全本地、开源、无服务器 | 账号数据不出本机 |
| 扩展性 | 硬编码单平台 | Platform Adapter 接口 | 新平台 = 一个插件 |

## 7. 结论与建议

1. **赛道成立**：需求真实高频（每个深度网民都有数百沉睡关注），无直接竞品，官方不会做，开源工具是最佳供给形态。
2. **合规决定生死**：必须以"手动导入"为 MVP 默认路径公开传播；微信解密、自动取关作为高级能力隔离在显式授权之后（详见 [compliance-privacy.md](./compliance-privacy.md)）。
3. **MVP 聚焦"整理"而非"取关"**：先做跨平台聚合 + 多级分类 + 多维筛选（合规、无风控），把"批量取关"放到数据闭环验证之后（V1.0）。
4. **B站先行、微信殿后**：平台适配器按"合规可行性"排序——手动导入（全平台）→ B站（网页端数据相对开放）→ 小红书 → 微信（技术与合规风险最高）。
5. **护城河是架构与口碑**：适配器接口 + 开源社区贡献新平台，比功能堆砌更能形成长期壁垒。
