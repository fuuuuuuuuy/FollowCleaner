# FollowCleaner 用户故事与用例

> 按 Epic → Feature → Story 拆解，每条故事附验收标准（Given-When-Then）。优先级：P0 必须 / P1 应该 / P2 可以。

## 1. 参与者（Actors）

| 参与者 | 说明 |
|--------|------|
| 普通用户 | 在本机管理本人各平台关注列表的人（主要参与者） |
| 平台适配器 | 对接微信/B站/小红书等外部平台的模块（次参与者，系统扩展点） |
| 平台客户端/网站 | 微信 PC 客户端、B站/小红书网页端（外部系统） |
| 社区开发者 | 贡献第三方适配器的开源贡献者（V2.0 插件生态） |

## 2. 史诗总览（Story Map）

```
用户旅程：  接入数据  →  整理分类  →  浏览发现  →  批量清理  →  兜底恢复  →  持续维护
─────────────────────────────────────────────────────────────────────────────
Epic E1    E2 导入     E3 分类     E4 浏览      E5 批量     E6 取关     E7 回收站
           数据接入     管理        筛选         操作        执行        与日志
                                                          E8 统计概览
                                                          E9 设置/适配器
```

MVP 切片：每个阶段取最小闭环 —— 手动导入(E1) → 默认分类/移动(E2) → 筛选沉睡账号(E3) → 批量导出/归类(E4)。取关(E6)在 V1.0 闭环。

## 3. 史诗与故事明细

### Epic E1：数据接入

#### Feature E1.1 手动导入（P0，MVP）

**US-101｜P0**
> 作为 普通用户，我希望 下载标准 CSV/JSON 模板并填入关注数据后导入，以便 在不接入任何平台自动化的前提下开始使用。

- AC1：Given 用户在导入向导选择"手动导入"，When 点击"下载模板"，Then 获得含全部字段说明的 CSV/JSON 模板
- AC2：Given 用户上传 1000 行格式正确的 CSV，When 确认导入，Then 5 秒内全部写入并提示成功
- AC3：Given 文件存在格式错误，When 导入，Then 0 条写入并返回逐行错误报告（行号+原因）
- AC4：Given 重复导入同一文件，When 再次导入，Then 账号总数不增加，仅刷新更新时间

**US-102｜P1**
> 作为 用户，我希望 导入时做字段映射（我的表格列名与标准字段不一致），以便 不用手动改表头。

- AC1：上传非标准列名文件时出现字段映射界面，系统给出智能推荐映射
- AC2：未映射的必填字段阻止导入并提示

#### Feature E1.2 B站适配器（P1，V0.5）

**US-110｜P1**
> 作为 B站用户，我希望 授权后自动拉取我的关注列表（含关注时间/UP主类型），以便 免手工整理。

- AC1：导入向导选择哔哩哔哩后，引导完成网页端安全授权（只读 Cookie/会话）
- AC2：拉取的账号含昵称、UID、头像、关注分组、账号类型
- AC3：拉取中断后可续传，不重复写入
- AC4：全程在本机完成，凭据仅存于本机加密存储

**US-111｜P2**
> 作为 用户，我希望 适配器拉取互动数据（最近观看/点赞互动），以便 判断沉睡账号。

- AC1：可得互动指标写入 interaction_metrics；不可得字段标记 unknown 而非报错

#### Feature E1.3 小红书适配器（P1，V1.0）

**US-120｜P1**
> 作为 小红书用户，我希望 自动导入我的关注博主列表，以便 统一管理。
- AC：同 US-110 结构；能力矩阵声明 import=web-api/automation，riskLevel=caution

#### Feature E1.4 微信适配器（P2，V1.1，高级功能）

**US-130｜P2**
> 作为 微信用户，我希望 在显式开启高级模式并确认免责声明后，从本机微信数据只读导入公众号/视频号关注列表，以便 管理微信侧关注。

- AC1：高级模式默认关闭，开启时必须展示完整风险告知并要求勾选确认
- AC2：仅读取本机数据库，不修改、不上传任何微信数据
- AC3：微信版本不受支持时明确提示并降级到手动导入，不崩溃
- AC4：解密密钥仅在内存中使用，不写入日志/磁盘

#### Feature E1.5 数据去重与合并（P1）

**US-140｜P1**
> 作为 用户，我希望 同一账号跨平台/重复导入时被正确识别，以便 数据不重复。
- AC1：以 `platform + platform_account_id` 为唯一键去重
- AC2：跨平台同名账号默认不合并（不同平台是不同账号），但可在详情页手动"标记为同一主体"（V1.1）

### Epic E2：分类管理

**US-201｜P0**
> 作为 用户，我希望 创建/重命名/删除多级分类，以便 搭建自己的关注管理体系。
- AC1：支持最多 5 级嵌套，第 6 级入口禁用
- AC2：同级分类重名实时拦截
- AC3：删除分类需二次确认，其下账号移入"未分类"，账号不丢失

**US-202｜P0**
> 作为 用户，我希望 拖拽分类节点调整层级与顺序，以便 高效整理。
- AC1：拖拽到节点上成为其子节点，拖拽到间隙调整顺序
- AC2：拖入自身或其子节点时拒绝并提示
- AC3：调整后重启应用结构保持

**US-203｜P0**
> 作为 用户，我希望 把账号拖进分类或通过批量操作分配分类，以便 快速归档。
- AC1：一个账号可属于多个分类
- AC2：批量分配为原子操作，失败整体回滚

**US-204｜P1**
> 作为 用户，我希望 给账号打标签（如"素材""待取关""朋友"），以便 跨分类灵活组织。
- AC1：一个账号可多标签；标签可独立筛选
- AC2：标签支持重命名（全局生效）与删除

**US-205｜P2**
> 作为 用户，我希望 系统给出智能分类建议（如按平台/类型/沉睡状态），以便 冷启动时快速建体系。
- AC1：导入后一键生成"建议分类"预览，用户可采纳/忽略/批量采纳

### Epic E3：浏览与筛选

**US-301｜P0**
> 作为 用户，我希望 用三栏工作台（分类树/列表/详情）浏览账号，以便 获得文件管理器式的熟悉体验。
- AC1：点击左栏分类，中栏展示账号；右栏展示选中账号详情
- AC2：10,000 账号量级滚动流畅（虚拟滚动 ≥50fps）

**US-302｜P0**
> 作为 用户，我希望 组合筛选平台、账号类型、关注时间、互动频率、状态，以便 精准定位目标账号。
- AC1：多条件为 AND 组合，结果实时更新
- AC2：已选条件以 chips 展示，可单独移除
- AC3："零互动 + 关注超 1 年"两步内可达

**US-303｜P0**
> 作为 用户，我希望 按昵称/ID/备注关键词搜索，以便 快速找到特定账号。
- AC1：输入即时模糊匹配；空结果有空状态引导

**US-304｜P1**
> 作为 用户，我希望 按关注时间/互动频率/昵称排序并切换表格/卡片视图，以便 按习惯浏览。

**US-305｜P2**
> 作为 用户，我希望 保存常用筛选条件为"智能视图"，以便 一键复用（如"每月待清理"）。

### Epic E4：批量操作

**US-401｜P0**
> 作为 用户，我希望 勾选账号并"全选当前筛选结果（含跨页）"，以便 大批量处理。
- AC1：全选数与筛选统计一致
- AC2：选中后底部浮动工具栏展示已选数量与可用操作

**US-402｜P0**
> 作为 用户，我希望 批量分配分类/打标签/移除分类，以便 一次处理几百个账号。
- AC1：操作显示进度、可取消
- AC2：结果 toast 反馈并写入操作日志

**US-403｜P1**
> 作为 用户，我希望 批量导出选中账号为 CSV/JSON，以便 在工具外使用（如运营素材库）。

**US-404｜P2**
> 作为 用户，我希望 批量操作前预览受影响账号，以便 确认范围无误。

### Epic E5：取消关注（高危）

**US-501｜P1（V1.0）**
> 作为 用户，我希望 在详情页对单个账号取关，以便 浏览时即时清理。
- AC1：手动导入数据源下取关按钮置灰并说明原因
- AC2：取关前弹确认；成功后账号进入回收站

**US-502｜P1（V1.0）**
> 作为 用户，我希望 对筛选出的账号批量取关，并有确认清单与防误触倒计时，以便 安全批量清理。
- AC1：确认弹窗列出全部待取关账号（>10 可折叠）
- AC2：≥10 个时确认按钮 3 秒倒计时
- AC3：必须展示风险提示文案

**US-503｜P1（V1.0）**
> 作为 用户，我希望 取关队列限速执行、可暂停/终止，以便 不触发平台风控。
- AC1：默认每账号间隔 3~8 秒随机，每批 ≤20 个暂停
- AC2：收到风控/验证码信号立即暂停，提示用户去平台处理验证，不强行重试
- AC3：关闭应用后任务状态持久化，重启可续

**US-504｜P1（V1.0）**
> 作为 用户，我希望 取关完成后看到成功/失败报告，失败项可重试，以便 掌握结果。

**US-602｜P2**

**US-603｜P2**
> 作为 用户，我希望 手动彻底移除回收站记录，以便 清理本地数据。

## 4. 核心用例文字描述

**用例 UC-1：首次导入并完成一次清理（主路径）**
1. 用户启动应用 → 进入导入向导
2. 选择平台与获取方式（包含：手动/适配器；扩展：微信高级模式授权）
3. 阅读数据处理告知并确认
4. 系统执行读取/解析 → 预览 → 写入本地库
5. 进入工作台 → 应用"零互动 + 关注超一年"筛选
6. 全选结果 → 批量分配到"待清理"分类（V1.0 起可直接批量取关）
7. （V1.0）批量取关 → 确认弹窗（倒计时）→ 限速执行 → 结果报告
8. 回收站可查，可跳回平台重新关注

**用例 UC-2：风控熔断（异常路径）**
- 批量取关执行中平台返回安全验证 → 系统立即暂停队列 → 提示用户到平台客户端完成验证 → 用户返回后点击"继续" → 队列从断点恢复（包含：失败重试、跳过失败项）。
