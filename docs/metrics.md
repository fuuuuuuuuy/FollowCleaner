# FollowCleaner 数据指标体系

> 桌面开源产品的指标原则：**本地统计为主，匿名上报默认关闭**。所有指标首先服务于用户自我观测（概览页）与开发者改进产品（用户显式开启的匿名遥测），不采集任何账号内容数据。

## 1. 北极星指标

**指标名称**：周活跃清理用户数（Weekly Active Cleaning Users, WACU）

**定义**：一个自然周内，至少完成一次"批量归类 或 批量取关 或 批量导出"操作的去重用户数（本地口径为去重设备）。

**选择理由**：本产品的核心价值不是"打开看看"，而是"完成一次关注资产整理动作"。以"完成管理动作"而非"启动"为北极星，避免虚荣指标，直接对应产品价值交付。

**目标值**：0 → 发布 6 个月达 500 WACU。

## 2. 一级指标（战略层）

| 维度 | 指标 | 定义 | 目标 | 频率 |
|------|------|------|------|------|
| 规模 | 累计安装量 | GitHub Release 下载数（按版本去重） | 6 个月 5,000 | 周 |
| 活跃 | WACU（北极星） | 周内完成管理动作的去重用户 | 500 | 周 |
| 激活 | 导入完成率 | 完成首次导入的用户 / 启动导入向导用户 | ≥ 85% | 周 |
| 价值 | 人均单次清理账号数（中位数） | 每次会话批量操作涉及账号数 | ≥ 20 | 周 |
| 质量 | 取关安全率 | 1 −（风控投诉数 + 误伤申诉数）/ 取关执行用户数 | ≥ 99.5% | 月 |
| 留存 | 次月留存 | 本月活跃用户在下月仍活跃比例 | ≥ 40% | 月 |
| 生态 | 社区贡献 | 外部适配器 PR 数 / Issue 数 | ≥ 3 PR | 月 |

## 3. 二级指标（战术层）

### 3.1 数据接入模块
| 指标 | 定义 | 用途 |
|------|------|------|
| 导入方式分布 | 手动 / 各适配器占比 | 判断适配器投入优先级 |
| 适配器成功率 | 适配器导入成功次数 / 发起次数 | 适配器健康度 |
| 适配器失败原因 Top3 | 版本不支持 / 授权失败 / 网络 | 指导适配器迭代 |
| 平均导入账号数 | 单次导入账号数中位数 | 用户规模画像 |

### 3.2 分类与浏览模块
| 指标 | 定义 | 用途 |
|------|------|------|
| 分类创建率 | 创建过 ≥1 个自定义分类的用户占比 | 分类功能渗透 |
| 平均分类深度 | 用户分类树最大层级均值 | 验证 5 级上限合理性 |
| 筛选使用率 | 使用过 ≥1 个筛选条件的会话占比 | 筛选器价值 |
| 热门筛选组合 | 最常组合的筛选条件 | 预置"智能视图"依据 |
| 搜索使用率 | 使用搜索的会话占比 | 搜索价值 |

### 3.3 批量操作与取关模块
| 指标 | 定义 | 用途 |
|------|------|------|
| 批量操作渗透率 | 使用批量操作用户 / 活跃用户 | 核心功能采用 |
| 取关漏斗转化率 | 见 4.1 | 识别清理路径瓶颈 |
| 批量取关占比 | 批量取关账号数 / 总取关账号数 | 批量价值验证 |
| 风控熔断率 | 触发风控暂停的队列 / 总取关队列 | 限速策略校准 |
| 回收站恢复率 | 跳回重新关注数 / 取关总数 | 误操作率观测（越低越好，但>0 说明兜底有用） |

## 4. 漏斗设计

### 4.1 核心清理漏斗（导入 → 取关）

| 步骤 | 事件 | 说明 | 关注点 |
|------|------|------|--------|
| 1 | import_start | 发起导入 | — |
| 2 | import_complete | 导入成功 | 步骤1→2：导入完成率（目标 ≥85%） |
| 3 | filter_apply | 应用筛选 | 步骤2→3：用户是否开始"发现" |
| 4 | batch_action（归类/导出） | 完成整理动作（MVP 阶段终点） | — |
| 5 | unfollow_dialog_open | 打开取关确认弹窗 | 步骤4→5：整理到清理的转化 |
| 6 | unfollow_execute | 确认执行取关 | 步骤5→6：确认弹窗流失（倒计时/恐惧） |
| 7 | unfollow_result（success>0） | 取关成功 | 步骤6→7：执行成功率（风控/失败） |

**瓶颈假设与对策**：
- 步骤 1→2 流失：导入门槛过高 → 强化手动模板引导、适配器环境自检前置
- 步骤 5→6 流失：用户恐惧误操作 → 优化确认弹窗文案、回收站兜底说明前置
- 步骤 6→7 流失：风控/失败 → 限速策略校准、失败重试引导

## 5. 三级指标（埋点/事件字典）

### 5.1 事件规范

命名：`动作_对象_结果`（如 `import_complete`、`unfollow_result`）
全局属性（自动附加）：`app_version`、`os`、`platform_target`（操作的平台）、`session_id`、`timestamp`
**禁止采集**：昵称、账号 ID、备注、头像、任何内容字段；平台凭据绝不离开本机。

### 5.2 事件清单

| 事件名 | 触发时机 | 关键属性 | 优先级 |
|--------|----------|----------|--------|
| app_launch | 应用启动 | version, os, first_run(bool) | P0 |
| import_start | 发起导入 | platform, method(manual/adapter) | P0 |
| import_complete | 导入结束 | platform, account_count, duration_ms, result(success/fail/partial) | P0 |
| adapter_selfcheck_fail | 适配器自检失败 | platform, reason | P1 |
| category_create | 新建分类 | depth, is_rename | P1 |
| category_delete | 删除分类 | child_count, account_count | P2 |
| filter_apply | 应用筛选 | conditions_count, result_count, preset(none/silent/old...) | P1 |
| search_submit | 关键词搜索 | result_count | P2 |
| batch_select_all | 全选筛选结果 | selected_count | P1 |
| batch_action | 批量操作完成 | action_type(assign_category/tag/export/unfollow), count, duration_ms | P0 |
| unfollow_dialog_open | 打开取关确认 | count, mode(single/batch) | P1 |
| unfollow_execute | 确认执行 | platform, count, mode | P0 |
| unfollow_result | 队列完成 | platform, success_count, fail_count, risk_triggered(bool) | P0 |
| risk_pause | 风控熔断 | platform, queue_progress | P0 |
| recycle_restore_click | 回收站跳回关注 | platform | P2 |
| dashboard_view | 概览页浏览 | — | P2 |
| telemetry_opt_change | 遥测开关变化 | enabled(bool) | P1（合规审计用） |

### 5.3 本地统计（不上传，直接展示给用户）

概览页数据全部来自本地库实时计算：关注总数、平台分布、互动频率分布、关注时间分布、累计取关数、分类覆盖率。

## 6. 隐私与合规的指标边界

1. 匿名遥测**默认关闭**，首次启动设置中明确询问；事件仅含聚合数字与枚举，不含自由文本
2. 本地数据库与遥测数据流物理隔离：抓包可见任何含账号标识的请求即为 P0 缺陷
3. 遥测开关变化本身被记录（`telemetry_opt_change`），用于合规审计
4. 不做任何广告/第三方追踪 SDK 接入
