## 2. 背景与目标

### 2.1 背景

用户的社交关注关系分散在微信（公众号/视频号）、哔哩哔哩、小红书等多个平台，关注列表"只进不出"：

- **平台侧**：关注数是内容消费与留存的基础指标，各平台系统性弱化取关能力——微信无关注列表导出、无批量取关；B站/小红书仅提供单级分组；无任何平台提供"按互动频率/关注时间"的管理视图。
- **用户侧**：重度用户关注数普遍 300~2000+，其中大量为"关注后从未再看"的沉睡账号，手动逐个清理成本极高、且无决策依据（不知道该取关谁）。
- **市场侧**：无跨平台关注管理的直接竞品；灰色脚本功能单一、无安全兜底、隐私不透明；微信数据导出类开源项目已验证技术路径与社区接受度。

### 2.2 目标

**用户目标**：让用户在 10 分钟内完成一次"关注列表体检"——看清自己关注了谁、谁在沉睡，并能安全地批量归类与清理。

**产品目标**：
- 业务（开源项目）目标：GitHub 1k Star，形成社区贡献适配器的生态雏形
- 体验目标：核心清理路径（导入 → 筛选 → 批量操作）≤ 5 步
- 信任目标：数据 100% 本地处理、代码开源可审计，0 起因工具导致的账号事故

### 2.3 成功指标

| 指标 | 基准值 | 目标值（发布后 6 个月） | 统计周期 |
|------|--------|------------------------|----------|
| 周活跃清理用户（WAU） | 0 | 500 | 周 |
| 导入流程完成率 | — | ≥ 85% | 周 |
| 单次会话批量操作账号数（中位数） | — | ≥ 20 | 周 |
| 取关操作安全率（无风控/无误伤投诉） | — | ≥ 99.5% | 月 |
| 次月留存率 | — | ≥ 40% | 月 |
| GitHub Star / 社区适配器 PR 数 | 0 | 1000 Star / ≥ 3 个外部适配器 PR | 累计 |

> 指标定义与埋点详见 [metrics.md](./metrics.md)。

## 3. 用户画像

### 3.1 核心用户：数字囤积清理者（主力，约 60%）

- **身份**：22~35 岁，互联网从业者/学生，网龄 8 年以上，关注账号 500+
- **场景**：年末/换手机/信息焦虑爆发时，想"清理一下关注列表"，打开各 App 翻了两页就放弃
- **痛点**：不知道关注了谁、不知道谁值得留、手动清理太累、怕误取关找不回来
- **期望**：一个像"文件管理器"的工具，快速看清全貌、批量处理、操作可反悔
- **技术接受度**：能接受桌面工具、手动导入文件；对开源/隐私敏感

### 3.2 次要用户：内容创作者/运营者（约 25%）

- **身份**：自媒体作者、MCN 运营、品牌新媒体
- **场景**：管理多个账号的关注关系（对标账号、素材源、互动客户），需要分类归档
- **痛点**：关注即素材库，但平台内无法高效分组；跨平台素材源分散
- **期望**：多级分类 + 标签 + 导出，把关注列表变成"信息源数据库"
- **特殊诉求**：数据导出（CSV）、分类配置可备份

### 3.3 次要用户：隐私与信息焦虑敏感者（约 15%）

- **身份**：对数字足迹敏感的用户
- **场景**：希望最小化自己在各平台的关注暴露面，定期"断舍离"
- **痛点**：担心工具本身窃取数据；担心批量操作触发封号
- **期望**：开源、本地、操作可控（限速、预览、确认）

## 4. 需求范围

### 4.1 In Scope（V1.0 范围内）

- 多平台关注数据导入：**手动导入（CSV/JSON 模板，全平台通用）** + 哔哩哔哩适配器 + 小红书适配器 + 微信适配器（高级功能）
- 统一账号数据模型（基本信息、关注时间、互动频率、账号类型、平台）
- 多级分类管理（创建/命名/编辑/删除/拖拽排序，最大 5 级）+ 标签
- 账号列表浏览：按平台/分类/关注时间/互动频率/账号类型/关键词多维筛选与搜索
- 批量操作：多选、全选（按筛选结果）、批量分配分类、批量打标签、批量导出
- 取消关注：单个/批量取关、操作前预览确认、限速执行、回收站快照兜底
- 数据导出（CSV/JSON）与本地加密存储
- 平台适配器插件化架构（为社区扩展预留）

### 4.2 Out of Scope（明确不做）

- ❌ 任何服务器端账号数据存储 / 云同步（V1.x；端到端加密同步列入 V2.0 探索）
- ❌ 粉丝管理（管理"谁关注我"）——仅管理"我关注谁"
- ❌ 内容发布、评论、点赞等非关注关系操作
- ❌ 移动端 App（系统沙箱决定不可行，见竞品分析）
- ❌ 读取/处理他人账号数据（产品层面强制本机本人账号）
- ❌ 账号买卖、刷量等任何灰产功能
- ❌ 绕过平台付费/风控的破解行为

## 6. 核心功能详细说明

### 6.1 数据导入（F-IMPORT）

#### 功能概述
将各平台关注列表安全导入本地数据库，支持手动导入与平台适配器两种路径，适配器统一遵循插件接口。

#### 用户故事
作为 用户，我希望 用最简单的方式把我在各平台的关注列表导入工具，以便 在一处统一管理，且不担心账号安全。

#### 前置条件
- 首次使用进入导入向导；已导入过数据时可从「设置 → 数据源」再次进入
- 微信适配器需用户显式开启"高级模式"并阅读免责声明

#### 交互流程
1. 用户选择平台（微信/B站/小红书/手动导入）→ 系统展示该平台支持的获取方式与风险说明
2. 用户选择获取方式：
   - **手动导入**：下载 CSV/JSON 模板 → 用户在平台侧自行整理/复制数据 → 上传文件
   - **适配器导入**：系统执行环境自检（如微信需检测到 PC 客户端进程/数据库路径）
3. 系统展示权限与数据处理告知（"数据仅存本机，不上传"），用户勾选确认
4. 系统执行读取/解析，显示进度条与分阶段状态
5. 读取完成 → 展示**导入预览**（账号数、字段完整度、重复项），用户确认后写入本地库
6. 导入完成页：成功数/失败数/跳过数，失败项可下载错误报告

#### 异常流程
| 异常场景 | 系统响应 |
|----------|----------|
| 微信 PC 客户端未运行/版本不受支持 | 提示原因，给出"手动导入"降级路径与支持版本清单 |
| 数据库解密失败（版本升级等） | 明确提示"当前微信版本暂未适配"，引导提交 Issue，不崩溃 |
| 文件格式错误/字段缺失 | 逐行报错（行号+原因），提供修正模板，不写入脏数据 |
| 网络平台读取中断（B站/小红书） | 断点续传/重试，已获取数据保留 |
| 重复导入 | 按 `平台 + 平台账号ID` 去重，提示"新增 X 条，更新 Y 条" |

#### 验收标准（AC）
- [ ] AC1：手动导入 1000 行 CSV，字段完整时成功率 100%，耗时 < 5s
- [ ] AC2：错误模板文件导入时 0 条数据写入，且错误报告精确到行号
- [ ] AC3：重复导入同一文件，账号数不增长，更新时间被刷新
- [ ] AC4：微信适配器在未获显式授权时不可执行，且界面不展示可绕过入口
- [ ] AC5：导入全程无任何网络请求携带账号数据（可通过抓包/网络面板验证）
- [ ] AC6：适配器执行失败不影响主程序，给出可读错误信息与降级建议

### 6.2 分类管理（F-CATEGORY）

#### 功能概述
多级分类树 + 标签体系，支持创建、命名、编辑、删除、拖拽排序，账号与分类多对多。

#### 用户故事
作为 用户，我希望 用多级分类和标签整理关注账号，以便 像管理文件一样管理上千个关注对象。

#### 前置条件
- 本地库中至少有 1 个账号
- 系统预置默认分类：`未分类`（不可删除）、各平台名默认分类

#### 交互流程
1. 左栏分类树顶部「+ 新建分类」→ 输入名称 → 选择父分类（默认根级）→ 回车创建
2. 右键分类节点：重命名 / 新建子分类 / 删除 / 排序（上移下移/拖拽）
3. 拖拽分类节点可调整父子关系与顺序；拖入另一节点即成为其子分类
4. 删除分类：弹窗提示"该分类下 N 个账号将移动到「未分类」，不会删除账号"，需确认
5. 账号可通过拖拽到分类节点、或批量操作栏分配分类；一个账号可属于多个分类 + 多个标签

#### 异常流程
| 异常场景 | 系统响应 |
|----------|----------|
| 分类层级达到 5 级 | 禁止新建子分类，提示"最多支持 5 级" |
| 同级分类重名 | 实时校验提示"同级已存在同名分类" |
| 删除非空分类 | 二次确认，账号归入「未分类」，操作可在回收站撤销分类删除 |
| 拖拽到自身或其子节点 | 拒绝并高亮提示，防止循环引用 |

#### 验收标准
- [ ] AC1：支持 5 级嵌套，第 6 级创建入口禁用
- [ ] AC2：拖拽排序后重启应用，顺序与层级保持不变
- [ ] AC3：删除分类后其下账号 100% 落入「未分类」，无账号丢失
- [ ] AC4：分类树支持 200+ 分类节点时渲染无卡顿（<100ms 交互响应）
- [ ] AC5：一个账号可同时归属 ≥2 个分类与 ≥5 个标签

---

### 6.3 浏览与筛选（F-BROWSE）

#### 功能概述
三栏工作台，支持按平台、分类、标签、关注时间、互动频率、账号类型、状态多维筛选与关键词搜索。

#### 用户故事
作为 用户，我希望 按互动频率和关注时间快速筛选出"沉睡账号"，以便 决定取关对象。

#### 交互流程
1. 左栏点击分类节点 → 中栏展示该分类下账号（含子分类可开关"递归显示"）
2. 中栏顶部筛选器：平台（多选）、账号类型（个人/公众号/视频号/官方号）、关注时间（区间/快捷：近3月/半年前/1年前）、互动频率（高/中/低/零互动，阈值可在设置中调整）、状态（关注中/已取关）
3. 搜索框输入昵称/ID/备注 → 实时模糊匹配
4. 列表支持排序：关注时间、互动频率、昵称；支持表格/卡片视图切换
5. 点击账号 → 右栏详情：头像、平台、主页链接、关注时间、互动统计、所属分类/标签、操作按钮（打开主页/取关）

#### 验收标准
- [ ] AC1：组合 3 个以上筛选条件时结果正确，筛选条件以标签 chips 展示可单独移除
- [ ] AC2：10,000 账号量级下列表滚动流畅（虚拟滚动，帧率 ≥ 50fps）
- [ ] AC3："零互动 + 关注超 1 年"一键筛选可达，≤ 2 次点击
- [ ] AC4：筛选条件可保存为"智能视图"（V1.1），V1.0 至少保证条件在会话内保持

---

### 6.4 批量操作（F-BATCH）

#### 功能概述
勾选/跨页全选/按筛选结果全选后，批量分配分类、打标签、导出、取消关注。

#### 用户故事
作为 用户，我希望 把筛选出的 200 个沉睡账号一次性选中并批量处理，以便 不用逐个操作。

#### 交互流程
1. 列表首列勾选框；表头复选框支持"全选当前筛选结果（含跨页）"
2. 选中后底部浮起批量工具栏：已选 N 个 ｜ 分配分类 ▾ ｜ 打标签 ▾ ｜ 导出 ▾ ｜ 取消关注 ▾ ｜ 取消选择
3. 选择「分配分类」→ 弹出分类树勾选目标分类 → 确认 → 即时完成并 toast 反馈
4. 选择「取消关注」→ 进入取关确认流程（见 6.5）

#### 验收标准
- [ ] AC1："全选筛选结果"数量与筛选统计数一致，跨页有效
- [ ] AC2：批量分配分类为原子操作，中途失败可整体回滚
- [ ] AC3：批量操作期间显示进度，可取消；取消后已处理部分在结果报告中列明
- [ ] AC4：批量操作均写入操作日志

---

### 6.5 取消关注（F-UNFOLLOW，高危核心）

#### 功能概述
在分类视图内对单个或批量账号执行取消关注，具备预览确认、限速执行、结果报告、回收站快照四重保障。

#### 用户故事
作为 用户，我希望 安全地批量取关，并在误操作时能找回，以便 敢用批量清理功能。

#### 前置条件
- 该平台适配器支持取关能力（手动导入模式下取关能力不可用，按钮置灰并提示"该数据源仅支持本地管理，取关请前往对应平台"）
- 设置中取关二次确认为开启（默认开启）

#### 交互流程
1. 用户触发单个/批量取关 → 弹出**确认对话框**：
   - 列出待取关账号清单（头像+昵称+平台，超过 10 个折叠为"等 N 个"可展开）
   - 风险提示文案（平台风控、不可在平台侧撤销）
   - 倒计时确认按钮（批量 ≥10 个时按钮 3 秒倒计时，防误触）
2. 用户确认 → 进入执行队列：
   - 适配器按平台执行取关，**默认限速**（如每账号间隔 3~8 秒随机，每批次 ≤20 个后暂停）
   - 实时进度：成功/失败/跳过计数，可随时暂停/终止
3. 执行完成 → 结果报告页：成功 N、失败 N（原因：风控拦截/网络/已取关）、失败项支持"稍后重试"
4. 所有被取关账号写入**回收站**：保留快照（昵称/平台/主页链接/取关时间），保留 30 天
5. 回收站支持"重新关注"（跳转对应平台主页）与"彻底移除记录"

#### 异常流程
| 异常场景 | 系统响应 |
|----------|----------|
| 平台返回风控/验证码 | 立即暂停队列，提示"平台已触发安全验证，请在平台客户端完成验证后继续"，不强行重试 |
| 单账号取关失败 | 记录失败原因，继续队列其余项，不整体中断 |
| 执行中关闭应用 | 队列状态持久化，重启后提示"有未完成的取关任务，是否继续" |
| 适配器不支持取关 | 按钮置灰 + 说明文案 |

#### 验收标准
- [ ] AC1：批量取关必须经过确认弹窗，≥10 个时确认按钮有 3 秒倒计时
- [ ] AC2：取关请求严格限速，默认间隔 ≥3 秒且随机化，限速参数用户可在设置调严不可调松至低于安全下限
- [ ] AC3：触发风控时队列自动暂停，0 次强行重试
- [ ] AC4：取关成功的账号 100% 进入回收站，快照字段完整
- [ ] AC5：回收站"重新关注"可正确跳转平台对应主页
- [ ] AC6：取关操作全程记录操作日志（时间/账号/结果/来源筛选条件）
- [ ] AC7：手动导入数据源下取关入口不可用

---

### 6.6 统计概览（F-DASHBOARD）

#### 功能概述
首页仪表盘：关注总量与平台分布、互动频率分布（沉睡占比）、关注时间分布、累计清理成果。

#### 验收标准
- [ ] AC1：各图表数据与本地库实时一致（导入/取关后刷新）
- [ ] AC2：点击图表数据块（如"零互动 320 个"）可直接跳转对应筛选结果列表

---

### 6.7 平台适配器架构（F-ADAPTER，技术底座）

#### 功能概述
定义统一 `PlatformAdapter` 接口，每个平台一个适配器（独立模块/动态加载），声明能力矩阵：`import`（导入）、`interaction`（互动数据）、`unfollow`（取关）、风险等级。

接口核心契约（伪代码）：
```ts
interface PlatformAdapter {
  id: string;                    // 'bilibili' | 'xiaohongshu' | 'wechat' | ...
  displayName: string;
  capabilities: {
    import: 'manual' | 'local-read' | 'web-api' | 'automation';
    interactionData: boolean;
    unfollow: boolean;
  };
  riskLevel: 'safe' | 'caution' | 'advanced';  // 决定授权与免责流程
  fetchFollows(): Promise<FollowAccount[]>;
  unfollow(accountId: string): Promise<UnfollowResult>;
}
```

#### 验收标准
- [ ] AC1：新增一个平台适配器无需修改核心代码（插件注册机制）
- [ ] AC2：适配器崩溃/超时不影响主进程与其他适配器
- [ ] AC3：适配器能力矩阵驱动 UI（不支持的能力自动置灰/隐藏）
- [ ] AC4：社区适配器有签名/来源标识，加载第三方适配器需用户确认风险

## 8. 非功能需求

### 8.1 性能
- 10,000 账号量级：列表交互响应 < 100ms，导入 1000 条 < 5s
- 批量取关队列在后台执行不阻塞 UI
- 应用冷启动 < 2s

### 8.2 兼容性
- Windows 10/11（x64）；macOS 12+（Intel/Apple Silicon）
- 微信适配器：明确声明支持的微信 PC 版本范围，版本不在范围时优雅降级
- 屏幕分辨率：1280×720 起可用，推荐 1920×1080

### 8.3 安全与合规
- **数据零外发**：除用户主动发起的平台请求外，账号数据不离开本机；无分析 SDK 默认开启
- 本地数据库 SQLCipher 加密，密钥由用户机器特征派生 + 可选用户密码
- 取关限速与风控熔断为强制下限，用户不可关闭安全下限
- 微信高级功能（本地数据库读取）须显式开启 + 免责声明确认
- 开源完整代码（含适配器），接受社区安全审计
- 详见 [compliance-privacy.md](./compliance-privacy.md)

### 8.4 可维护性
- 适配器与核心解耦，平台改版只需更新适配器
- 所有平台逆向/适配知识以文档沉淀（`docs/adapters/`），降低单点维护风险

## 10. 风险评估

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 微信版本更新导致解密失效 | 高 | 高 | 适配器独立迭代、社区共建适配、失败优雅降级到手动导入 |
| 自动取关触发平台风控/封号 | 中 | 高 | 强制限速、风控熔断、批次暂停、显著风险告知、默认引导手动模式 |
| 平台方法律投诉/DMCA | 中 | 高 | 合规分级设计、商标规避、MIT 开源、仅处理本人数据、准备下架应对预案 |
| 用户误操作大量取关 | 中 | 高 | 倒计时确认 + 回收站快照 + 操作日志 |
| 适配器维护人力不足 | 中 | 中 | 插件化 + 文档化 + 社区贡献机制 |
| 用户数据泄露（本地） | 低 | 高 | SQLCipher 加密、日志脱敏、无服务器攻击面 |
| 同名灰产工具损害声誉 | 中 | 中 | 官方发布渠道唯一化（GitHub Release）、签名发布、文档声明 |
